# NIUMA V3.1.5 仓库
## 开发动机
工作上看到别的同事总是将接收到的各种工作文件不加整理归类的全部放到桌面，哪怕有的人最开始是有整理归类，但是面对越来越多的工作收到越来越多的文件，最后也难免失守，桌面放了一堆杂乱不堪的文件。

我作为一个有洁癖看不得脏乱差的人，看到电脑系统内文件无法归类也会有看到房间没有收拾干净的错觉，而我自己哪怕一直在尽力分类整理，但确实也有些心有余而力不足。为了解决这个痛点，刚好又乘上vibe coding的快车，我决定自己开发一个工作任务的管理软件，兼顾工作文件的归纳整理，于是最后就诞生了这款软件。

## 声明
（1）由于这是根据我自身工作而开发的，所以该软件也仅仅针对我所在的单位系统，也即税务铁军系统。体制内电脑一般都是老破旧window电脑，哪怕在推行国产化的现在，国产系统我也基本只在市局、省局看到过，所以该软件也就没有考虑国产系统，只考虑了window系统尤其是window 7系统的兼容性。

（2）该软件主要是将基层税务局税源管理科室会接收到的工作粗略地分为催、查、报、办四类将工作任务分类，同时工作文件随工作任务进行归纳保存，然后我还加上了工作成果系统，方便季度或者年度归纳总结，但是工作成果系统我并没有实际测试，所以很可能有各种各样的问题，现在发布出来也是希望以后如果有人认可这个项目愿意继续优化改善的话可以继续完善系统。

（3）在最开始我的野心其实更大，基层税务工作有的人是懂得，所以更想做一个将工作任务管理和挂机游戏系统相结合的产物，这样上班打开软件就挂机，接到并完成工作任务可以升级、获取装备，最好再添加生涯、成就以及装备纸娃娃系统，然而这个设计实在太过繁杂，只好搁置放弃，也只能等以后有缘再继续了。

（4）由于该软件只在我的个人电脑和单位工作用的老破旧windows7 系统电脑上测试运行过，所以不能保证兼容性一定没问题，就我目前两个月的使用体验来看，最主要的任务管理和工作文件收纳功能暂时没发现大的问题。

（5）其他没什么好说的了，我基本把vibe coding的产物全部放出来了，包括最开始的需求文档等等，我也不知道我这是不是重复造轮子，但愿对铁军同志们尤其是同在苦逼税源管理工作的同志们能有些帮助。

那么以下是AI帮我写的项目主页概述

## 构建与验证

正式软件使用 Windows 自带的 Segoe UI，中文回退至 Microsoft YaHei UI / Microsoft YaHei（微软雅黑）。不加载、不嵌入 MiSans，首次克隆后无需下载字体；历史设计字体原包仅在本地作为前期资料保留。

在仓库根目录使用 `CMakePresets.json` 中的 `v3-staging-debug` 或 `v3-staging-release` 配置、构建和运行 CTest。`04_program/build/` 为可再生构建树；`06_test/data/`、`06_test/evidence/` 和 `06_test/reports/` 为可再生测试输出，清理后测试会重新创建。
构建需要 Qt5 Svg 开发模块；图标工具从统一 SVG 在构建目录中生成 ICO，不修改源码中的二进制资源。关闭图标采用 Microsoft Fluent UI，许可说明随交付包附带。
Windows 构建另需与 Qt5 Gui 配套的私有开发头文件，用于同步自定义边框的 Qt 几何缓存；交付包不增加运行时 DLL。

真实用户 `Data/`、工作目录和备份不得进入仓库、测试目录或交付 ZIP。当前交付包见 `05_product/NIUMA-V3.1.5-20261031.zip`，运行文件始终为 `Niuma.exe`，不随版本变化。当前为 3.1.5；后续优化依次递增至 3.1.9，再升级为 3.2.0。

Windows 11 使用系统圆角，Windows 7/8/10 使用带抗锯齿透明边缘的软件圆角及边框；窗口控制按钮完整自绘。兼容分支与静态导入审计属于本地检查，Windows 7 SP1 的实际主题、驱动及原生文件选择器仍需目标系统验证。
