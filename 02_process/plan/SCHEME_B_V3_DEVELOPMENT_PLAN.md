# NIUMA v3 · 方案 B 正式程序开发方案

版本：2026-09-23 · 计划与历史基线。正式程序迁移及本地打包已完成；后续执行状态以 `02_process/task.md` 为准。

## 1. 目标、决策与事实来源

目标是在保留 v2 全部业务语义、数据/文件契约的前提下，把 2026-09-22 定稿的方案 B 移入可交付的 v3 正式程序。方案 B 是唯一视觉与交互基线，不恢复 A/C，不重新设计或从截图反推界面。

已获用户确认的实施路线：**复用 v2 Qt 5.15 Widgets/C++17 源码并迁移方案 B 样式；先在隔离数据环境等价迁入，允许明确标记的 v2 UI→DAO 过渡耦合，随后按功能域分阶段解耦。**不把 Qt Designer `.ui` 作为本轮的事实源，也不把四层重构与首次视觉迁移捆成一次大改。

来源优先级：

1. 设计：`03_ui_design/FINAL_UI_HANDOFF.md`、`DESIGN_SYSTEM.md`、`../04_program/ui_preview/{SchemeBStyler.cpp,SchemeBStyler.h,v2_source_preview_main.cpp}`、`../03_ui_design/styles/scheme_b.qss`；定稿截图与报告仅作回归证据。
2. 功能：`04_program/legacy_v2` 中受控的 Qt Widgets、模型、DAO、服务与工具源码，及 `../V2_FEATURE_PRESERVATION_MATRIX.md`。
3. 页面/弹窗盘点：`03_ui_design/SCHEME_B_PRODUCTION_MIGRATION_CHECKLIST.md`。该文件包含 v2 入口、B 实现和无自动截图覆盖的项目。
4. 安全与兼容：`../MIGRATION_AND_ROLLBACK_V3.0.md`。其中不改 schema、状态字符串、编号、工作目录及 `.niuma` 目录包的原则仍有效。
5. S00 冻结与退出依据：`S00_V2_AND_SCHEME_B_BASELINE.md`、`UI_DAO_TRANSITION_DEBT.md`。

旧文档中 `.ui`/AUTOUIC、原生窗框、深色侧栏/暖灰工作区等内容与 B 定稿冲突，须在阶段 S00 显式标记为被本决策取代；不得在执行中混用两种 UI 路线。`02_process/DECISION_LOG.md` 中 ADR-002（Qt5/Win7 意图）及 ADR-004（生产数据不入 v3 工作区）继续有效；ADR-001、ADR-003 待更新为 superseded，而非删除历史。

## 2. 范围与非目标

本轮范围：主窗体/导航/全局控件、八个主页面、任务与资料详情、全部创建/编辑/成果/扫描弹窗、确认与系统选择链、键盘/焦点/缩放/滚动/状态反馈、隔离数据的功能和视觉回归、逐域解耦、发布与回退准备。

非目标：方案 A/C、Qt 6、云服务、新业务功能、数据库 schema 变更、工作目录改名、备份格式改造。旧审计指出的缺失四态、快捷键、可访问性与备份验证属于显式质量缺口；其中 UI 质量在本计划内补齐，备份格式/校验的超范围改动须另立需求，不得悄悄改旧格式。

## 3. 技术落地与安全边界

### 3.1 过渡结构

- `04_program/` 初期建立受控的 `legacy_v2/` 源码快照，按原有 `ui/ models/ database/ service/ utils/ resources/` 层级保留可编译关系；不从 v2 目录长期按 glob 直接编译。记录来源路径、版本/哈希与修改清单，采用显式 CMake source list。
- v3 正式入口与预览入口分开。`v2_source_preview_main.cpp:49-114` 会清空并种入独立数据库，只能用于预览/测试，绝不成为正式程序入口；v2 `src/main.cpp:46-118` 的启动/退出契约（工作目录、备份、跨天专注、30 天清理、退出导出）须逐项保留且在 staging 验证。
- 迁移期可在 `legacy_v2/ui` 保留原有 DAO/`QSqlQuery`，每一处登记为迁移债，禁止新增平行 SQL/业务规则。新写的展示组件不直接访问数据库。后续以稳定 DTO/用例从页面逐域移除这些依赖，最终实现 `presentation → application → domain`、`infrastructure` 实现端口。
- 方案 B 的基础样式由 v2 `neutral_modern.qss`、`scheme_b.qss` 与运行时修饰共同形成。首批可以移植修饰器来达到画面等价；之后把通用规则收敛到 QSS/控件，页面行为归还所属 View/服务。尤其 `SchemeBStyler.cpp:1329-1410` 的排序分页 SQL 必须在首页域解耦阶段前移出修饰器。
- 预览库、staging fixture 与真实数据路径通过明确配置隔离，默认开发/测试程序不得解析到 v2 或 v3 的真实 `Data`。禁止把数据库、WAL/SHM、日志、备份、附件纳入源码目录。修改备份/初始化/永久删除流程只在生成的虚构或审查后的脱敏 fixture 上演练。

### 3.2 兼容与回退

- 初期不改现有 schema、状态字符串、任务编号、工作目录结构、`.niuma` 包契约；测试与数据验证仅使用 `06_test/` 内 staging fixture，不读写、复制真实用户数据。
- 采用 Qt 5.15/C++17。开发与交付使用本机可复现的构建、staging CTest 和隔离启动验证；Win7、系统选择器、物理键盘、OS DPI 和真实数据副本演练不作为本地交付门槛。
