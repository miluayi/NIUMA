# 决策记录

## ADR-001：保留 Qt Widgets，改用 Qt Designer

- 日期：2026-09-01
- 状态：已被 ADR-005 取代
- 决策：继续 C++/Qt Widgets；`.ui` + AUTOUIC 取代 HTML→手写 C++ 布局流程。
- 理由：最大化复用已完成的 C++ 业务，显著缩小 UI 重构风险，并获得可视化布局源。
- 后果：自绘控件仍需 C++ 和运行时 Gallery 验证，Designer 不是全部像素的唯一验证手段。

## ADR-002：首轮保留 Qt 5.15/Win7 意图

- 日期：2026-09-01
- 状态：已接受，待发布工具链验证
- 决策：本轮以 Qt 5.15.18/C++17 设计与构建，不同步升级 Qt 6。
- 理由：v2 把 Win7 SP1 作为硬约束；平台升级会扩大 API、样式、部署和测试矩阵。
- 风险：Qt5 维护与安全成本更高；当前 MinGW 开发构建不等于已验证的 Win7 发布工具链。
- 复议条件：用户明确放弃 Win7，或发布维护成本超过兼容收益。

## ADR-003：恢复原生窗口框架

- 日期：2026-09-01
- 状态：已被 ADR-005 取代
- 决策：不继承 v2 的 FramelessWindowHint/自绘标题栏。
- 理由：恢复系统 resize、Snap、系统菜单、DPI 与辅助功能行为，减少无关维护面。

## ADR-004：生产数据不进入 v3 工作区

- 日期：2026-09-01
- 状态：已接受
- 决策：不复制 v2 的 Data、数据库、日志、备份、工作目录或附件；仅允许审查后的脱敏 fixture。
- 理由：避免误改真实数据、泄露与不可复现测试。

## ADR-005：方案 B 的 v2 Widgets 源码迁移与分阶段解耦

- 日期：2026-09-22
- 状态：已接受（用户确认）
- 决策：方案 B 是唯一 UI 定稿。正式程序复用 v2 的 Qt 5.15 Widgets/C++17 页面、弹窗、模型和业务语义，逐步迁入方案 B C++/QSS 样式与交互；不恢复 A/C，不以 Qt Designer `.ui` 重录页面，也不从截图反推界面。
- 过渡：S01–S12 可在受控的 `legacy_v2/ui` 保留现有 UI→DAO/`QSqlQuery` 耦合，逐处登记、不得新增。S13–S15 必须按功能域移入 application DTO/用例/端口，最终所有参与正式构建的 UI 源码均不直接依赖 DAO、`DatabaseManager`、`QSqlQuery`。
- 窗口与视觉：采用 B 定稿的无边框自绘壳、184px 侧栏、70px 标题栏、浅色外壳/白色工作区和 16px 工作区圆角；可访问性、键盘、缩放和窗口行为用可观察验收验证，而非沿用 ADR-003 的原生窗框要求。
- 约束：不改变 v2 schema、状态字符串、编号、工作目录或 `.niuma` 契约；预览/测试与真实 Data 严格隔离。ADR-002、ADR-004 继续有效。

## ADR-006：每阶段 E2E 与 simplify 收口门禁

- 日期：2026-09-22
- 状态：已接受（用户确认）
- 决策：每个 Sxx 开发阶段完成后，先编写该阶段的前后端 E2E 测试方案，再使用已接入的 Playwright MCP、LazyTesting MCP 和适用的 Qt/桌面自动化 MCP 执行；记录测试环境、fixture、场景、命令/工具输出、截图/视频（如支持）和失败项。E2E 未通过或工具未接入时，阶段不得标记完成。
- 适配边界：Playwright 原生只自动化浏览器页面；Qt Widgets 原生窗口须通过可用的桌面自动化/测试驱动或 LazyTesting 适配执行等价流程。若当前 MCP 不能控制该原生界面，记录为阻断，不伪称 Playwright 已覆盖。
- 收口：每次生成或修改代码、以及开发测试完成后，必须调用可用的 `/simplify` 技能进行范围内优化；随后重跑受影响的构建、单元/集成测试和 E2E。若 `/simplify` 或所需 MCP 未安装/不可调用，记录为阻断或明确豁免，不以人工声称替代工具执行。
