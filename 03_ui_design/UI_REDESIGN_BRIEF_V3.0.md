# NIUMA V3 UI 重设计简报

## 产品与用户

NIUMA 是面向基层税务干部的单人、本地、离线任务与资料台账。用户通常同时处理大量来源分散、截止日期不同、伴随文件的任务，并需要在年终回溯成果。核心不是“展示数据”，而是帮助用户在 30 秒内决定并完成下一步操作。

## 首要任务

1. 打开软件后立即知道今天最重要的 1–3 件事。
2. 快速创建、查找、筛选、打开和完成任务。
3. 在不打断工作的情况下理解任务状态、截止风险和文件归档位置。
4. 可靠处理空数据、筛选无结果、加载与错误，而不是看到空白页。
5. 完整使用键盘完成高频操作，同时保留清晰的鼠标路径。

## 当前定稿方向：方案 B

2026-09-22 起，方案 B 是唯一设计基线；以 `03_ui_design/FINAL_UI_HANDOFF.md`、`DESIGN_SYSTEM.md`、原型 C++/QSS 和定稿回归材料为准。本节以下的“台账工作台”及设计 dials 为 2026-09-01 历史提案，不再作为实施或验收依据。

视觉母题来自“可靠的工作台账”，而不是消费级待办卡片：左侧是稳定目录，右侧是可扫描、可操作的工作面。重复的线性结构建立秩序，少数暖色标记真正需要注意的内容。

### Design dials

| 维度 | 取值 | 含义 |
|---|---|---|
| 密度 | 中高 | 1440×900 下优先展示信息和动作；不用大面积装饰留白 |
| 对比 | 清晰但克制 | 深色导航、暖灰背景、白色工作面；状态不只依赖颜色 |
| 几何 | 低圆角、硬朗线条 | 常规 4–6px，主要靠分隔、间距和排版建立层级 |
| 温度 | 冷静中性 + 暖色提醒 | 蓝绿墨色作为操作色，陶土橙只用于焦点与提醒 |
| 动效 | 极少 | 只用于状态确认；支持减少动画，不阻塞操作 |
| 文案 | 直接、具体 | 用“新建任务”“清除筛选”“重试”，不使用含糊营销语 |

## 布局原则

- 使用方案 B 的无边框自绘窗口壳；通过实际缩放、拖动、最小化/最大化/关闭、焦点与键盘回归保证可用性。
- 侧栏只承担全局导航；页面内的筛选、数据状态和批量操作在主工作区完成。
- 首页不是等权卡片墙：今日专注为首要横向区，进行中任务为主要内容，周期提醒与月度概览为次要侧栏。
- 列表页面由页头、可换行筛选区、四态数据区、分页/批量操作组成。
- 设置中心保留 v2 工作目录、字典、导出、数据、关于、初始化的完整功能，按方案 B 当前页面与滚动规则呈现。
- 最小 940×580 时允许主工作区纵向滚动；筛选自动换行，禁止依赖页面级横向滚动。

## 无障碍与交互硬约束

- 所有可操作控件均进入 Tab 焦点链，并有清晰 `:focus` 样式和 accessible name。
- 标签通过 buddy 关联输入控件；重要状态同时用文字/形状表达。
- `QTextEdit` 中 Enter 始终换行；Ctrl+Enter 才可作为明确提交快捷键。
- Esc 关闭/取消，Ctrl+N 新建，Ctrl+F 搜索，Ctrl+S 保存，F5 刷新；Delete 仅在明确选择并可恢复/确认时执行。
- loading/content/empty/error 是统一组件契约；错误态提供可见重试。
- 任何重要操作都必须有正在处理、成功、失败和重复点击语义。

## 范围

本轮包括：主窗口、8 个页面、任务/资料/周期/成果/扫描等弹窗、设计令牌、集中 QSS、键盘/状态/响应式契约与视觉回归。

本轮不包括：新增业务功能、云同步、移动端、AI/OCR、数据库 schema 改造、工作目录规则改名、Qt 6 迁移。
