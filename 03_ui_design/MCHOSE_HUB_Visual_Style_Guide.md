# MCHOSE HUB 视觉风格复用指南

> 用途：指导其他软件在结合自身真实功能的前提下，设计出接近 MCHOSE HUB 的视觉风格。
> 
> 证据来源：客户端运行时、安装包静态资源、网页端公开 HTML/CSS/JS 资源。本文只提炼视觉设计，不把设备专属功能当作通用模块。

## 1. 一句话风格

浅色、低噪、设备中心的专业控制台：用浅灰工作区承载白色面板，用克制蓝色表达重点操作，用轻阴影和圆角建立层级，用真实对象图片/模型让功能与对象产生联系。

关键词：浅色、低对比、白色表面、轻阴影、16px 卡片、8px 控件、设备预览、克制蓝色、适中信息密度、解释型设置。

## 2. 视觉边界

应保留：浅灰背景 + 白色内容面板；大面积留白；低对比边框；8/16px 分层圆角；轻阴影；蓝色重点操作；真实对象图或结构化预览；同一对象内用标签页切换能力。

应避免：整体深色电竞风；大量玻璃拟态、霓虹渐变和高饱和背景；每个字段都包成独立卡片；仅用颜色表达状态；为了模仿界面加入目标软件并不具备的功能。

设备外观主题和首页背景可以有明暗或个性化变化，但不能破坏浅色工作区的可读性。

## 3. 已确认视觉令牌

| 语义 | 已确认值/方向 | 使用方式 |
|---|---|---|
| 主文字 | `#151515`，网页端也出现 `#181818` | 标题、正文、关键数值 |
| 深色表面 | `#212225`、`#303134`、`#37383A` | 设备主题或局部深色控件 |
| 主强调 | `#005ce6`、`#3964e5` | 主按钮、选中态、链接、进度 |
| 次级表面 | `#F2F3F7` | 次级按钮、轻量操作 |
| 边框 | `#D7DEE3` | 普通按钮和低对比边界 |
| 危险/错误 | `#ea5e56` | 删除、恢复出厂、失败 |
| 警告 | `#e6a23c` | 版本、连接提醒、注意事项 |

客户端运行时确认正文字体优先级为 `MiSans, PingFang SC, Helvetica, sans-serif, Arial`，基础正文约 `14px/20px`。

圆角与阴影：设备卡片 `16px`；普通按钮/输入/选择器约 `8px`；设备卡片阴影 `0 4px 12px rgba(0,0,0,.08)`；悬浮提示层可使用更强的 `0 6px 16px rgba(0,0,0,.18)`。

建议使用语义 token：

```css
:root {
  --mc-bg-app: #f5f6f8;
  --mc-surface: #ffffff;
  --mc-surface-subtle: #f2f3f7;
  --mc-text-primary: #151515;
  --mc-text-secondary: #6f7782;
  --mc-border-subtle: #d7dee3;
  --mc-accent: #3964e5;
  --mc-danger: #ea5e56;
  --mc-warning: #e6a23c;
}
```

`--mc-bg-app` 的精确值应按目标软件重新验收；重点是语义关系，不是机械复制固定色板。

## 4. 布局配方

### 4.1 对象列表页

```text
浅灰工作区
└─ 设备/对象卡片网格或列表
   ├─ 对象图与名称
   ├─ 连接/可用状态
   ├─ 外观版本色样
   └─ 进入详情/快捷操作
```

客户端实测内容区顶部留白约 `32px`，设备列表间距约 `24px`。平铺模式强调识别和图片，列表模式强调密度和批量浏览；两者共享数据和操作状态。

### 4.2 对象详情页

```text
白色或浅色详情工作区
├─ 左侧：对象身份、配置档案、导入/批量
├─ 顶部：同一对象的能力标签
├─ 中央：动作库、参数表单或设置分组
└─ 右侧：对象图片/模型/实时反馈
```

如果目标软件没有实体对象，右侧替换为实时预览、结果面板或状态摘要，不要保留空白装饰区。

## 5. 组件规范

### 5.1 对象卡片

白色表面、16px 圆角、轻阴影、清晰主图、简短名称与状态。白色对象色样增加内描边；hover 只增强边界或阴影，不做跳跃式放大。

### 5.2 按钮

客户端运行时确认次级按钮接近 `#F2F3F7` 背景、13px 字号、38px 高度、8px 圆角；普通按钮为白色背景、`#D7DEE3` 边框、8px 圆角。主按钮用蓝色，危险操作用危险色，文案说明结果，如“应用”“重新连接”“恢复出厂”。

### 5.3 标签页与设置分组

标签页用于同一对象的能力切换，不用于瞬时动作。当前标签用蓝色、底线或浅色背景表达，并配合文字。设置分组采用“标题 + 简短解释 + 控件组”，不要每个字段都独立成卡片。

### 5.4 参数与预览

参数同时显示数值、单位、范围或 Tips。高级设置应解释用途和影响。对象图/3D 模型/分层示意图应参与识别、部位标注和当前选中反馈，而不只是装饰。

## 6. 状态视觉

| 状态 | 视觉策略 |
|---|---|
| 默认 | 白色表面、低对比边界 |
| hover | 轻微边界/阴影变化 |
| 选中 | 蓝色强调 + 文字/图标/形状 |
| 禁用 | 降低对比度，并说明原因 |
| 加载 | 局部 loading，保留上下文 |
| 成功 | 小面积成功提示 |
| 警告 | 橙色语义色 + 影响说明 |
| 错误 | 红色语义色 + 恢复动作 |
| 高风险 | 警示弹窗 + 影响范围 + 危险确认 |

颜色不能成为唯一状态信号，应同时使用文字、图标、边界、位置或形状。

## 7. 迁移步骤

1. 列出目标软件真实对象、能力、参数和状态。
2. 采用“对象列表 → 对象详情 → 能力标签 → 编辑/预览”的骨架。
3. 先建立语义色、字体、圆角、阴影和间距 token。
4. 先做卡片、按钮、标签页、设置行和状态提示，再做页面。
5. 用真实数据长度、空态、错误态和窄窗口验收。
6. 最后加入目标软件自身的图片、图标和品牌色，不让装饰替代信息层级。

## 8. 验收清单

- [ ] 工作区是否浅色、低噪且层级明确？
- [ ] 卡片是否约 16px、控件是否约 8px，而不是全都同角度？
- [ ] 阴影是否足够轻？
- [ ] 蓝色是否只用于重点操作或选中态？
- [ ] 主图/预览是否帮助理解功能？
- [ ] 高级参数是否有单位、范围或解释？
- [ ] 连接、禁用、加载、失败和高风险状态是否可识别且可恢复？
- [ ] 是否避免加入目标软件并不具备的 MCHOSE 专属功能？

## 9. 证据说明

客户端真实运行时确认了 A7 V2 Ultra 的浅色详情页、三段式布局、设备预览、字体与部分控件尺寸；网页端公开资源进一步确认设备卡片 16px 圆角、`0 4px 12px #00000014` 阴影、8px 控件圆角、颜色切换和同源组件分包。不同型号可能有深色设备主题、灯效/屏幕/音频专属页面，复用时以目标软件实际功能为准。
