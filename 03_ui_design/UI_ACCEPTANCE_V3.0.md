# NIUMA V3 UI 验收标准

以下要求以可观察行为为准。审阅者无需阅读实现代码即可判断通过与否。

## R1：方案 B Widgets 单一事实源

- 主窗口、页面和弹窗复用 v2 Qt Widgets 源码结构；视觉/交互以 `03_ui_design/FINAL_UI_HANDOFF.md`、方案 B C++/QSS 与迁移清单为准。
- 正式 target 使用显式源码清单和受控 v2 快照；不得从相邻 v2 目录按 glob 编译、引入预览入口/种子数据库，或恢复早期 Designer `.ui` 表单。

## R2：主窗口与尺寸

- 使用方案 B 的无边框自绘窗口壳；最小化、最大化、调整大小、拖动、关闭、焦点和键盘行为均可用。
- 1440×900 无截断；1280×720 仍可完成所有高频任务；940×580 不出现页面级横向滚动，必要区域仅纵向滚动。
- 侧栏和主工作区在 100%、125%、150%、200% DPI 下不重叠。

## R3：键盘路径

- 从窗口顶部开始连续按 Tab，可访问导航、搜索、主操作、筛选、表格和分页，焦点始终可见。
- Ctrl+N 打开新建任务；Ctrl+F 聚焦搜索；F5 刷新；Esc 取消/关闭；Ctrl+S 保存。
- `QTextEdit` 内按 Enter 只换行，Ctrl+Enter 才按界面明确说明提交。
- 表格可用方向键选择、Enter 打开详情；Delete 不会在无选择或未确认时永久删除。

## R4：数据四态

每个数据列表都有且只能显示以下一种状态：loading、content、empty、error。空数据库与筛选无结果的文案不同；error 包含重试且重试不会叠加并发请求。

## R5：首页层级

- 今日专注在首屏最醒目，最多 3 项，空态给出从进行中列表添加的操作提示。
- 进行中任务是页面主要信息面；周期提醒和本月概览处于次级位置。
- 重点、今日专注、截止风险与任务状态均有文字/形状，不只靠颜色。

## R6：列表与筛选

- 筛选区在窄宽度换行，不挤出视口；清除筛选一步可达。
- 表格列可调整；关键列在 1280×720 可见，非关键列可有列选择/详情承载，不依赖整页横向滚动。
- 选中、悬停、键盘焦点三种状态可以区分。

## R7：表单与弹窗

- 创建/编辑保留 v2 各自的字段、布局与业务语义；是否在后续解耦中合并实现不得改变可观察行为。
- 必填、格式错误和保存失败在字段附近或统一错误区说明；不会只用 Toast。
- 默认按钮、取消按钮、危险操作与关闭语义清楚；重复点击保存不会创建重复记录。

## R8：对比与反馈

- 正文和关键控件达到 WCAG 2.1 AA 常用对比度目标；状态色组合需实测。
- Toast 可关闭、可由辅助技术感知；不阻挡主操作，错误不会只显示 3 秒后消失。
- 减少动画设置下不执行非必要位移/淡入淡出。

## R9：业务兼容

- UI 重构阶段不改变 v2 的状态值、编号、目录映射、金额/日期存储、备份包和数据库结构。
- 任务创建、编辑、完成、取消完成、删除、恢复、今日专注、资料、成果和周期任务的回归均通过。

## R10：视觉回归

- 主窗口、首页、任务列表、任务表单、任务详情、设置页和关键错误/空态都有固定环境截图基线。
- 基线变更必须附设计原因与人工确认，不能由测试自动覆盖。

## R11：阶段 E2E 与代码收口

- 每个 Sxx 阶段完成前，必须有该阶段的 E2E 测试方案，列明隔离 fixture、前后端流程、成功/取消/失败/重复操作场景和预期证据。
- 浏览器适配表面使用 Playwright MCP；原生 Qt Widgets 使用可用的 LazyTesting 或桌面自动化 MCP。工具不可调用或不支持目标表面时，阶段记录 blocker，不得把手工检查标记为 MCP E2E 通过。
- 每次生成/修改代码及开发测试完成后，调用可用 `/simplify`，并重跑受影响构建、测试和 E2E；优化不得改变已验收行为。
