# NIUMA V3.2.5 产品需求与现行行为

更新：2026-11-10。软件名称为 NIUMA（铁军牛马任务日志），内部代号为“铁军贰号”。本文件记录当前正式程序的用户可见行为。历史方案、未实现设想和测试阶段记录以 `../02_process/` 为准。

项目作者：miluayi。设置中心作者信息与此一致。

首页、任务和资料列表及弹窗中的文字信息支持鼠标拉选，选中后可按 Ctrl+C 或右键复制。拖选只在原位置标蓝文字，不生成输入框、不移动单元格文字、不改变原鼠标样式，也不修改任务或资料；单击名称仍打开对应详情，拖选则不打开。首页名称同样区分单击与拉选。任务及资料详情在显示前完成字体与布局准备，避免打开后可见的布局微调。新建/编辑输入框沿用原生编辑与复制行为。

详情等只读文字在点击和复制时不显示文本输入竖线，仍保留原位选区、拖选、Ctrl+C 和右键复制。可编辑输入框保持正常的输入光标。

## 1. 使用范围与页面

NIUMA 是本地 Qt5 Widgets 桌面程序，主界面包含首页、任务管理、周期任务、参考资料、年度成果、统计、回收站和设置中心。程序使用 SQLite 保存结构化数据，以用户选择的工作目录保存任务、资料及附件。正式交付版本为 V3.2.5，运行文件固定为 Niuma.exe。下一轮软件优化版本为 3.2.6。

首页显示今日专注、进行中任务、周期提醒与概览；任务管理支持创建、筛选、查看、编辑、重点标记、完成、取消完成和删除。周期任务提供模板及到期提醒。参考资料支持独立创建、编辑、查看与删除。年度成果、统计和回收站沿用各自页面；设置中心管理工作目录、来源、标签、办理人、导出设置、扫描导入和备份恢复。

界面所用 Segoe UI 常规/半粗/粗体、微软雅黑及其 UI 字体的常规/粗体、Segoe UI Symbol 作为未修改的字体资源内置于 Niuma.exe，启动时先通过 Qt 应用字体接口注册，再创建启动提示和主界面；仅作用于本进程，不要求用户安装字体，也不写系统字体目录或字体注册表。迁移到没有这些系统字体的环境时仍可加载内置字体。保留现有字号、字重和界面样式；不同操作系统的文字渲染和抗锯齿仍可能有差异，不承诺逐像素相同。项目维护者已于 2026-11-05 确认持有相应应用内嵌及分发授权；字体版权、版本及校验记录见正式资源中的 fonts/NOTICE.txt，字体不属于项目源码的开放授权范围。

Windows 当前登录会话中保持单实例；再次启动 EXE 会唤回已有窗口，已最小化时恢复，已最大化时保持最大化，后启动的进程不执行数据库及启动维护。主窗口保留无边框样式，支持任务栏的系统最小化操作。

主窗口支持四边、四角的原生拖动缩放，保留最小尺寸与最大化工作区约束。Windows 11 使用系统 DWM 圆角、边框和阴影，不再用整数像素区域裁切主窗口；旧系统使用软件抗锯齿圆角及边框。标题栏图标为 30px，与窗口及 Windows EXE 图标共用一份蓝底白色居中 N 的矢量源；构建时由该源生成多尺寸 ICO，图形不依赖字体基线，窗口控制按钮为 46×32px、连续等距排列，最小化/最大化保留既有线框，关闭使用 Microsoft Fluent UI Dismiss 16 Regular 原始 SVG、以 14px 显示；按可见图标校准上边距与右边距相等，并在 V3.1.2 将两侧留白从约 30px 同步减至约 18px（缩小 40%），三个按钮保持同一水平中心线，保留现有文字标识和布局。缩放事件只调整必要控件的位置，不重复遍历整页设置样式。界面字体采用 Segoe UI，中文回退至 Microsoft YaHei UI/微软雅黑；保留字号、字重设置。此组合用于对齐 Windows 桌面界面观感，未验证为 Codex/ChatGPT 的内部字体。

所有自定义对话框、下拉列表及日期/年度选择器使用统一的圆角和边框。对话框和日期/年度选择器在 Windows 11 通过 DWM 绘制；Windows 7/8/10 通过透明窗口与小范围边缘绘制保留抗锯齿圆角，取消像素区域裁切，阴影按系统合成能力提供。普通下拉框与自动补全列表在各 Windows 版本统一使用一层透明表面绘制圆角、边框和柔和阴影，去除系统菜单阴影及内外层重复边框；列表内容与滚动条位于圆角内部，避免白色直角背景露出。圆角与下拉阴影不依赖 Aero。最大化时使用直角以贴合工作区，恢复窗口后重新显示圆角。窗口控制按钮的背景、按下和键盘焦点外观完整自绘，不交给旧系统主题。页面、表格和列表共用逐像素滚动策略：鼠标滚轮按可视区域调整距离、使用相同的 180ms 缓动；触控板连续像素位移直接响应，嵌套列表达到边界后衔接外层页面。

任务及资料搜索在原有文本字段之外，支持当前附件文件名的模糊匹配，包括子目录文件；匹配文件名而不读取文件内容，跳过内部信息文件。附件名结果与其他筛选条件相交后再排序、计数和分页。

## 2. 任务、资料与工作区

- “催／查／报／办”分类标记以任务管理列表为统一标准，分别使用紫、浅黄、蓝、绿背景与黑色居中文字。首页、任务详情（含周期生成任务）、周期模板列表和统计分类分布共用相同的字体、尺寸、圆角、颜色和文字位置，支持不同显示缩放比例；统计分类分布的对应颜色同步统一，统计数值与计算规则不变。
- 任务详情（含周期生成任务）和资料详情的名称区域支持每行 15 个中文汉字、三行共 45 字，显示前完成字体和尺寸准备；名称按纯文本显示。周期模板新建/编辑的名称输入区同样支持三行自动换行，保留 Enter 保存，粘贴换行在保存时转换为空格。
- 首页的今日关注、进行中任务和周期提醒，以及任务、周期模板、资料、年度成果、回收站等页面的列表，文字被实际截断时，鼠标悬停显示完整内容气泡；适用于各文本列。完整可见的文字不弹气泡，调整列宽、滚动和刷新后按当前显示尺寸判断。名称中的尖括号等字符按原文显示，保留原位拖选复制和单击打开详情。
- 普通下拉框关闭 Qt5 的展开快照动画，直接显示已准备好的透明圆角表面，避免展开期间黑色边框闪烁；保留既有柔和阴影、自动补全、键盘选择和 Esc 关闭。
- 任务编号为 `YYYYMMDD-NNN`。任务目录名提供编号、分类和名称；资料目录名提供编号和名称。只有名称符合解析规则的目录才能由扫描导入。
- 任务可记录来源、事项标签、办理人、截止日期、任务说明、重点标记和附件目录结构。资料可记录来源、标签、说明和附件。附件文件保留在目录中，扫描恢复时不重建逐个附件的数据库清单。
- 周期任务列表在来源后显示“标签”列，展示模板新建或编辑时保存的事项标签；编辑后刷新列表同步显示。该列沿用列表的截断气泡与复制行为。
- 任务标签、周期任务标签、参考资料标签分别保存和管理。各自的新建/编辑标签选项、输入新标签后的收录及最近使用排序仅作用于所属体系；可拥有同名标签，增删、修改或停用互不影响。设置中心在“标签管理”中切换“任务标签／周期任务标签／参考资料标签”，为所选体系添加或删除标签；切换时清空未提交的输入草稿。来源和办理人管理沿用现有规则。
- 升级时将原共享标签字典一次性复制为独立字典，保留名称、顺序及停用状态，并补入既有周期模板、资料记录实际使用的标签；原记录的标签文字保持不变。初始出现同名标签不代表共享数据，之后各自管理，重启不重新复制。周期模板生成任务仍继承模板的标签文字，此操作不合并两套标签字典。
- 每个任务目录根部的隐藏文件 `.niuma-task.json` 保存任务详情及成果信息，包括成果原登记时间。成果新增、编辑和删除时同步写入。每个资料目录根部的隐藏文件 `.niuma-reference.json` 保存资料详情。旧任务启动时补建缺失文件，并从数据库补写已有成果。
- 工作目录下有六个根目录：`01_工作区_进行中`、`02_历史归档`、`03_年度成果`、`04_参考资料`、`05_回收站`、`06_他人办理`。已完成任务在历史归档的年/月目录中。
- 状态变更需要移动任务目录。目标目录已存在、附件复制尚未完成或文件被占用而导致移动失败时，程序保持原状态并提示重试；用户关闭占用文件后再次操作。
- 任务和资料列表默认按创建年度显示本年数据。年度选择器采用年份网格，支持十年翻页和“全部年度”。选择年度立即同步起止日期到该年度全年并刷新列表，重选同年也恢复全年范围。选择全部年度时，日期控件显示本年全年，但默认查询所有年份，手动修改范围后再搜索才启用日期约束。
- 分类、来源、标签、状态、办理人和年度选择即时生效；只有名称或编号文本、手动调整的日期范围需要点击搜索。年度切换保留已提交的关键词，不提交草稿文本；其他下拉项沿用已搜索的关键词和日期条件。搜索与所有已选条件共同作用，无匹配记录时显示零结果占位。参考资料的年度、来源和标签遵循相同规则。
- 办理人筛选保留“全部办理人”入口，其后固定为“本人”“非本人”，其余具体姓名按中文拼音正序排列；姓名来自启用字典及未删除任务，包括往年任务。“非本人”汇总所有办理人不是“本人”的任务，兼容旧记录的空办理人，且与其他筛选条件共同作用。
- 任务表在截止日期后显示完成日期；已完成组及单独筛选“已完成”时均按实际完成时间倒序，兼容空格与 ISO 格式时间，缺失完成时间的记录排在其后，同时间按编号倒序。
- 附件删除、截止日期清除和顶部搜索清除的“×”使用红色；窗口关闭按钮保持原样。
- 已完成任务没有成果时，详情的成果信息卡片右上角显示“补录成果”。已有成果时显示“修改成果”和右侧红色“删除成果”，两按钮水平对齐，上方和右侧留白均为 20 px。三个操作沿用详情按钮的字号、高度和内边距。
- 年度成果表的单个标记居中，两个标记并排居中。列宽容纳两个完整标记，左右留白相等。单击成果行的数据单元格打开关联任务详情，“操作”列提供该成果的“编辑”和“删除”。
- 完成重点任务或为已完成的重点任务补录时，成果表单默认勾选“重点成果”，可手动取消。保存表单才会生成成果记录，跳过时仅保留任务的完成状态。
- 两个入口的编辑表单均回填原有字段，保存后保留成果原来的关联任务和归属年份。确认删除会移除该条成果，关联任务保留。年度成果在操作后更新列表、汇总和分页。已完成任务的最后一条成果删除后，详情重新显示“补录成果”。

## 3. 扫描恢复与冲突

程序启动时校对工作目录，并扫描任务和资料目录的新增项。原路径失效时，用户可选择迁移后的“工作目录”或其上级目录。合法且无冲突的目录会被导入；目录名恢复基础字段，隐藏 info 文件补充详情。

扫描导入时从任务文件恢复成果的全部字段，并保留原登记时间和归属年份。启动匹配已有任务或合并目录时，已有成果优先保留，缺少成果时从匹配的任务文件补入。

任务所在目录决定恢复后的状态：进行中目录为“进行中”，历史归档为“已完成”，回收站为“已删除”并出现在回收站页面，他人办理目录为“他人办理”。旧版他人办理目录缺少可确认的办理人时使用内置值“非本人”；已有具体姓名时保留姓名。回收站信息文件中的删除前状态用于后续恢复。

同编号目录、目录名与 info 内容不一致或 info 无效时进入扫描导入冲突列表。用户可保留并更名，也可合并；任务和资料的冲突字段逐项选择实际值，无差异字段不可编辑。合并附件时同名文件改名留存，避免覆盖。

## 4. 备份与恢复

设置中心提供简易备份和全量备份。简易备份保留数据库、配置、工作目录结构及隐藏 info 文件，不复制任务附件；全量备份包含整个工作目录。全量备份前显示工作目录体积并再次确认，主窗口底栏也显示该体积。两种备份的恢复规则见 [Backup_Recovery_V3.0.md](Backup_Recovery_V3.0.md)。

## 5. 数据与交付边界

正式 ZIP 只交付程序及运行依赖，不包含用户数据库、日志、测试程序、截图或测试工作目录。所有回归使用 `../06_test/` 中的隔离数据；在真实数据上执行备份或恢复前，应由用户选择目标并核对内容。
