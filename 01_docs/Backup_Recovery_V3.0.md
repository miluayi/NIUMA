# NIUMA V3.0 备份、迁移与恢复

更新：2026-11-08。当前实现入口为 `../04_program/legacy_v2/service/BackupService.cpp`、`ScanMatchService.cpp` 和 `application/maintenance/StartupUseCase.cpp`。

## 1. 备份类型

手动备份生成带时间戳的 `.niuma` **目录**，包含 `database.db`、`config.json`、`manifest.json`，并在配置了有效工作目录时包含 `workdir/`。清单记录数据库 SHA-256、数据库大小、创建时间、`backup_type` 和工作目录体积；旧备份包仍可能使用历史清单版本号。备份前执行 SQLite WAL checkpoint。默认备份目录最多保留 10 份自动/安全备份。

| 类型 | `backup_type` | 工作目录内容 |
| --- | --- | --- |
| 简易 | `simple` | 目录结构及任务、资料隐藏 info 文件；不包含普通附件文件 |
| 全量 | `full` | 整个工作目录，包括附件；开始前显示目录体积并二次确认 |
| 未配置工作目录 | `database_only` | 只有数据库、配置和清单 |

自动备份和程序目录中的 `NIUMA_auto.niuma` 用于日常保护；手动备份可选择简易或全量。交付产品 ZIP 不等于 `.niuma` 数据备份。

V3.2.2 的数据库包含任务、周期任务和参考资料三套独立标签字典，两种备份均随完整数据库保留这些字典。恢复旧版共享标签数据库后，初始化时执行一次性拆分：保留原名称、顺序、停用状态及记录中的标签文字，补入周期模板与资料实际使用的标签。两张新字典表在同一事务内建立，失败回滚并停止初始化；已拆分的数据库重启或恢复后不再从任务标签重新复制。恢复出厂设置会清空三套字典。

## 2. 恢复已有备份

恢复前校验清单中的数据库 SHA-256。程序先生成当前数据库的回退副本；含工作目录的备份先复制到暂存目录，再将现有工作目录重命名留存于同级目录，最后替换数据库并重新初始化。失败路径尝试回退数据库与工作目录。简易备份恢复不可能找回未被打包的附件；需要附件时应使用全量备份或另行保留原工作目录。

恢复操作会改变本地数据，选择备份时应核对包类型和目标工作目录。工作目录体积展示是决定全量备份开销的提示，不代表备份后文件大小。

## 3. 迁移路径与扫描导入

将安装目录和工作目录复制到新位置后，如果旧工作目录路径不可用，启动时可选择新工作目录或其上级目录。程序更新已知路径，并扫描进行中、历史归档、参考资料、回收站和他人办理目录；年度成果目录不参与任务扫描。任务编号须满足 `YYYYMMDD-NNN`；不符合规则的目录不会作为新任务导入。

目录名恢复任务编号、分类和名称；任务 info 恢复来源、标签、说明、办理人、截止日期、重点标记等详情。资料目录名恢复编号与名称；资料 info 恢复来源、标签和说明。任务附件仍在磁盘目录中，扫描仅判断目录是否含子目录，不建立逐附件记录。

扫描位置决定任务状态：进行中→进行中，历史归档年/月→已完成，回收站→已删除，他人办理→他人办理。回收站任务的删除前状态写在 info 文件中；无具体办理人且确定为他人办理时使用“非本人”兜底。没有 info 的旧目录仍可恢复基础字段，无法从目录推出的详情保持空值或使用上述兜底规则。

## 4. 冲突处理

同编号目录、目录名与 info 不一致、info 无效时不静默覆盖。扫描导入窗口提供勾选、全选、保留更名和合并。逐字段选择框直接显示候选值，无差异字段置灰；附件合并遇到同名文件时以新名称留存。处理完冲突后应核对目录、任务状态、办理人和附件。
