# NIUMA V3.0 开发与维护计划

更新：2026-11-06。本文件只给出现行维护顺序。逐轮已完成事项和具体测试结果以 `../02_process/task.md` 为准，早期设计迁移计划为过程记录。

## 当前基线

- 正式代码在 `../04_program/legacy_v2/`，采用 Qt 5.15 Widgets、C++17、SQLite 和 CMake；设计定稿材料在 `../03_ui_design/`。
- V3.0 已具备八个主页面、任务与资料隐藏 info、工作目录扫描导入、逐字段冲突处理、简易/全量备份恢复及“非本人”兜底办理人。
- 正式交付包在 `../05_product/`，只保留最新 ZIP。用户数据不属于仓库和交付包。

## 后续变更顺序

1. 先明确受影响的页面、数据字段、工作区目录和旧数据兼容规则，再改正式源码。
2. 使用 `../06_test/` 下的独立数据验证创建、修改、移动、删除、扫描、备份与恢复；绝不以真实 Data 试验。
3. 软件源码、资源或构建行为变更时，先构建，再运行相关 CTest 与完整 CTest；涉及界面时检查实际 Qt 抓图，并明确其不是物理桌面验证。纯文档、生成物清理、Git/GitHub 提交推送只检查相关文件及同步状态，不重复软件测试、抓图与打包。
4. 测试通过后更新 `../02_process/task.md` 的实际结果，打包 Release 到 `../05_product/`，核对包内容和隔离启动，只保留最新交付 ZIP。
5. 清理可再生的构建、缓存、旧测试输出；保留正式源码、CTest 源码和当前设计定稿资料。Win7 兼容性和系统原生选择器仍需真实目标环境验证，不能用本地 CTest 推断。
6. 当前版本为 3.2.1（资源数字版本 3.2.1.0）；下一轮软件优化为 3.2.2，依次至 3.2.9，再到 3.3.0。应用版本、设置页、EXE 版本资源、CMake 版本和 ZIP 名称保持一致；运行文件固定为 Niuma.exe。纯文档与 Git 发布不递增软件版本。
